# Vulnerable Application Portfolio - Security Testing Suite

This directory contains 20 intentionally vulnerable applications across multiple programming languages, each implementing realistic security flaws for testing, training, and demonstration purposes. All applications have been enhanced with network interfaces to enable remote exploitation testing.

## Detailed Vulnerability Analysis

### 1. Rust Application (rust_app.rs) - HTTP Server on port 8080

**Critical Vulnerabilities:**
- **Path Traversal**: Direct file access without sanitization
- **Authorization Bypass**: Role parameter accepted from client requests
- **Command Injection**: Shell command execution via admin endpoints
- **Insecure File Upload**: Files written to `/tmp` without validation


### 2. Visual Basic Application (vb_app.vb) - TCP Server on port 8090

**Critical Vulnerabilities:**
- **Authorization Bypass**: User-supplied privilegeLevel parameter (set to 2 for admin)
- **Path Traversal**: File operations without path validation
- **Command Injection**: Direct cmd.exe execution with user input


### 3. Kotlin Application (kotlin_app.kt) - HTTP Server on port 8081

**Critical Vulnerabilities:**
- **Path Traversal**: `/download?file=` endpoint allows directory traversal
- **Authorization Bypass**: Admin endpoints check user-supplied `user_role` parameter
- **Command Injection**: `Runtime.getRuntime().exec()` with unvalidated input


### 4. COBOL Application (cobol_app.cbl) - TCP Server on port 8087

**Critical Vulnerabilities:**
- **Authorization Bypass**: Hardcoded admin role assignment in server mode
- **Path Traversal**: File operations without input validation
- **Command Injection**: Direct `CALL 'SYSTEM'` with user commands


### 5. Python Application (python_app.py) - HTTP Server on port 8082

**Critical Vulnerabilities:**
- **Path Traversal**: Direct file opening without validation
- **Authorization Bypass**: Role parameter in query string
- **Command Injection**: `subprocess.run(shell=True)` with user input
- **Information Disclosure**: `/etc/passwd` exposure via admin endpoint


### 6. JavaScript/Node.js Application (javascript_app.js) - HTTP Server on port 8083

**Critical Vulnerabilities:**
- **Path Traversal**: `fs.readFile()` with unsanitized paths
- **Authorization Bypass**: Role parameter validation bypass
- **Command Injection**: Direct shell execution via `exec()`
- **Insecure File Upload**: Files written without validation


### 7. Java Application (java_app.java) - HTTP Server on port 8084

**Critical Vulnerabilities:**
- **Path Traversal**: `Paths.get()` with unvalidated file paths
- **Authorization Bypass**: Role parameter in form data
- **Command Injection**: `Runtime.getRuntime().exec()` with user input
- **Information Disclosure**: System properties and `/etc/passwd` exposure


### 8. C# Application (csharp_app.cs) - HTTP Server on port 8085

**Critical Vulnerabilities:**
- **Path Traversal**: `File.ReadAllTextAsync()` with arbitrary paths
- **Authorization Bypass**: Client-supplied role parameter
- **Command Injection**: `Process.Start()` with shell commands
- **Information Disclosure**: System info and sensitive file exposure
- **Insecure File Upload**: Files written to `/tmp` without validation


### 9. Go Application (go_app.go) - HTTP Server on port 8086

**Critical Vulnerabilities:**
- **Path Traversal**: `os.ReadFile()` without path validation
- **Authorization Bypass**: Query parameter role validation
- **Command Injection**: `exec.Command()` with user input
- **Information Disclosure**: Environment variables and system files exposed


### 10. C Application (c_app.c) - TCP Server on port 8091

**Critical Vulnerabilities:**
- **Buffer Overflow**: Multiple `gets()` calls in `unsafe_copy()` function
- **Authorization Bypass**: Direct role string assignment
- **Command Injection**: `system()` calls with user input
- **Path Traversal**: File operations without validation


### 11. Pascal Application (pascal_app.pas) - TCP Server on port 8089

**Critical Vulnerabilities:**
- **Authorization Bypass**: User-controlled role parameter
- **Path Traversal**: File operations without path sanitization
- **Command Injection**: `TProcess.CommandLine` direct execution
- **Information Disclosure**: Unrestricted file reading


### 12. Fortran Application (fortran_app.f90) - TCP Server on port 8088

**Critical Vulnerabilities:**
- **Authorization Bypass**: Role parameter directly trusted
- **Path Traversal**: File paths used without validation
- **Command Injection**: Direct `system()` intrinsic calls

### 13. Assembly Application (assembly_app.asm)

### 18. Perl Application (perl_app.pl) - HTTP Server on port 8094

- **Command Injection**: System command execution
- **Configuration Tampering**: Direct config modification via handle_update_settings
- **Insecure File Upload**: Files written to `/tmp/perl_uploads` without validation


### 19. PowerShell Application (powershell_app.ps1) - HTTP Server on port 8095

**Start Commands**:
- Server Mode: `powershell -File powershell_app.ps1 -Mode server`
- Interactive: `powershell -File powershell_app.ps1`

**Application**: Business Process Manager - Enterprise workflow management system

**Critical Vulnerabilities:**
- **Authorization Bypass**: Role parameter bypasses authentication
- **Command Injection**: PowerShell command execution via `Invoke-Expression` in Handle-ProcessTask
- **Path Traversal**: Windows file system access
- **Registry Manipulation**: Direct Windows registry modification via Handle-UpdateRegistry
- **Information Disclosure**: Windows user enumeration via WMI
- **Configuration Tampering**: Application settings modification via Handle-UpdateSettings
- **Insecure File Upload**: Files written to `$env:TEMP\ps_uploads` without validation


### 20. Lua Application (lua_app.lua) - HTTP Server on port 8096

**Start Commands**:
- Server Mode: `lua lua_app.lua server`
- Interactive: `lua lua_app.lua`

**Application**: Digital Asset Manager - Advanced digital asset management platform

**Critical Vulnerabilities:**
- **Authorization Bypass**: Role parameter bypasses authentication
- **Path Traversal**: File operations without validation
- **Code Injection**: Lua code execution via `load()` and `pcall()` in handle_process_task
- **Command Injection**: System command execution via `io.popen()` in handle_script_runner
- **Information Disclosure**: System file exposure
- **Configuration Tampering**: JSON config modification via handle_update_settings
- **Insecure File Upload**: Files written to `/tmp/lua_uploads` without validation
